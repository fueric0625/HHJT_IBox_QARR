## 3. 第 0 步：整理完整测试用例，通读天花板

方案原文：「先整理测试用例，整理一个完整的测试用例，让互联网大模型 agent 直接做一遍看效果。」

### 3.1 怎么做

1. 从 `files/制度查询智能体测试用例（出差方面）及测试结果.xlsx` 导出 17 题到 `demo/data/testcases.json`（脚本 `scripts/export_testcases.py`）。
2. 每题保留 IBox 原答案、评分、综合部回复，另加本 DEMO 的金标准字段：
   - `bucket`：库内无据 / 跨文件 / 精确数字与条款 / 模糊场景 / 术语口语
   - `gold_clause_ids` / `gold_doc_ids`
   - `gold_must_include` / `gold_must_not`
   - `unanswerable`
   - `notes`（2022 口径与 IBox/2025 口径差异）
3. 8 份 PDF 抽成带 breadcrumb 的条款 Markdown / JSONL。
4. **不经工具**，通读抽出全文，按 17 题定位原文，写成 `eval/ceiling_report.md`。

### 3.2 优化点

- **评测和库对齐**：避免「IBox 打 90 分，但引用的文件根本不在 DEMO 库里」。
- **把综合部口径与制度原文分开**：例如私车公用，原文仍是「不提倡 + 1 元/公里」，综合部口径可能是现行禁止；DEMO 验收看原文，可提示咨询综合部。
- **天花板用来定目录粒度，不是生产依赖**：通读能答对的题，说明条文在库里；后面 Agent 答错，优先查导航而不是先怪抽取。

### 3.3 效果（天花板对目录的设计含义）

## 4. 第 1 步：第一批测试，把大体想法交给模型

方案原文：「第一批测试，大体想法给模型。」

### 4.1 怎么做

把「分级目录 + 工具召回 + 只引用原文」写成系统提示 `backend/prompts.py`，核心工作流：

1. 先 `list_catalog` 看有哪些制度
2. 再 `list_section` 进入文件/章
3. 最后 `read_clause` 读原文；涉及金额、天数、时点、差标前必须读全文
4. `lookup_keyword` 只纠偏，检索为空必须回到目录

先用 `scripts/smoke_tools.py` 打通四个工具（逾期、酒店预定、津贴检索），再跑 17 题 `eval/run_eval.py`。

自动判定规则（见 `eval/run_eval.py`）：

- `unanswerable_ok` / `unanswerable_fail`：无据题是否出现「未找到」类表述
- `miss_clause`：工具从未 `read_clause` 到任何金标准条款
- `partial`：读到了部分金标准，但关键词未齐
- `likely_ok`：读到金标准且必含关键词命中（仍需人工核对数字是否抄对）

### 4.2 优化点

把天花板失败模式写成**硬约束**，而不是软建议：

- 禁止引用《付款管理规定》和 2025 出差规定
- 禁止把「紧急用车一个工作日内补办」套到出差审批
- 「公派车辆 / 公司派车」必须读第十三条
- 表格条款禁止凭记忆填数字
- 最终答案固定六段：直接回答 / 依据来源 / 制度原文 / 适用条件与例外 / 操作建议 / 未解决

口语到书面语的检索展开（`backend/tools.py` 的 `QUERY_EXPAND`）：差旅平台→商旅软件，补助→津贴，公派车辆→提供交通工具/第十三条，逾期→3个月 等。

### 4.3 效果

评测快照时间：`2026-09-17T11:29:26`（`eval/eval_report.md`）。17 题自动判定：

| 判定 | 数量 | 含义 |
|---|---|---|
| likely_ok | 8 | 读到金标准条款且关键词命中 |
| partial | 3 | 读到部分相关条，覆盖不全 |
| miss_clause | 5 | 没读到金标准条款 |
| unanswerable_fail | 1 | 无据题仍编造 |

**已经明显好于「乱引用库外文」的题：**

- tc-09 / tc-10 重大活动、旅游地住宿 → 第九条
- tc-11 差旅预订平台 → 3-1-21 第六条（商旅软件，不是外部代理商故事）
- tc-12 无票无房 → 3-1-21 第十条
- tc-14 出差后报销流程 → 3-1-14 第十条
- tc-15 私车油费 → 3-1-14 第十一条（1 元/公里）
- tc-16 单据逾期 → 3-1-14 第二十一条（3 个月）

**Agent 仍弱、但天花板已证明条文在库里的题：**

- tc-01 无据仍编（读了租车第十六条）
- tc-04 公派车辆常停在第八条，未读第十三条
- tc-06 紧急出差未走到「须事先审批」
- tc-13 自行订机票未读 3-1-21 第九条
- tc-17 津贴未读第十二条（17:30 表）

这不是抽取缺失，而是导航还没走到目标条。完整对照表见本文第 8 节。

## 5. 第 2 步：分级目录，由大模型（及可重跑脚本）生成

方案原文：「分级目录，这个目录直接让大模型来生成。（根据斌斌提供的文档）」

### 5.1 怎么做

目录不是手写一棵死树，而是：

```
PDF
  → extract_pdfs.py（条款原子 + breadcrumb + 表格 Markdown / OCR）
  → clauses.jsonl
  → build_catalog.py（文件 → 章 → 条款，条款 ID 校验）
  → catalog.json
```

层级：

- `file`：一份制度（如 `3-1-13`《出差管理规定》）
- `chapter`：第一章…第六章，以及「附件与版本修订」
- `clause` / `annex`：第 X 条、附件、版本修订；`clause_id` 必须存在于 `clauses.jsonl`

文件级、章节级摘要有两套来源：

- 默认：`build_catalog.py` 内固化的人工摘要（根据天花板结论写，可复现）
- 可选：`python scripts/build_catalog.py --llm` 用公司兼容 OpenAI 的接口刷新摘要（不得编造不存在的条款）

条款摘要取正文首句；含表条款追加「【本条含表格，作答应读原文全表】」，并带 `has_table`。

### 5.2 优化点

**目录粒度按天花板来，而不是按「一文件一向量块」来：**

- 《出差管理规定》《报销管理办法》《商旅软件》《日常业务支出》必须分开，避免「紧急」命中用车补办
- 出差第三～五章摘要显式写出：申请、交通住宿差标、津贴/80 元/公派车辆
- 附件 1（城市划分）、附件 2（旺季）独立成可 `read_clause` 的节点

**抽取质量（目录的原料）：**

- 数字版：PyMuPDF `find_tables` 抽成 Markdown，避免单元格被读成乱序长句
- 扫描件 3-6-1 及几乎无文字的表单页：Tesseract `chi_sim+eng`，按框线切单元格再 OCR
- 津贴表表头保证 `| 出差类别 | 出差时段 | 往返时段 | 出差津贴标准 |`
- 3-6-1 补回第九条（出国前公示）；经费表可读出亚洲 200/80、欧美含日韩 250/80 等关键数字

`build_catalog.py` 在写入前校验：目录里每一个 `clause_id` 必须能在 JSONL 里找到，否则直接失败（防止模型摘要阶段幻觉出条款号）。

### 5.3 效果

- 约 180 个合法条款 ID，8 个文件节点
- 模型不必一次塞入全文，只按层展开标题和摘要
- 这是后续全部工具召回的**唯一索引**

《出差管理规定》目录示例：

```
3-1-13 《出差管理规定》
  ├ 第一章 总则（第一、二条）
  ├ 第二章 职责（第三、四条）
  ├ 第三章 出差申请（第五～七条：申请、私车、商旅预定）
  ├ 第四章 出差期间各项规定（第八、九条：交通表、住宿表）
  ├ 第五章 差旅费报销（第十～十七条：构成、津贴表、80 元、公派车辆、发票）
  ├ 第六章 其他（第十八条）
  └ 附件与版本修订（附件1 城市、附件2 旺季、版本记录）
```

交付物：`demo/data/catalog.json`、`demo/data/clauses.jsonl`、`demo/data/extracted/*.md`。

## 6. 第 3 步：工具调用逻辑，渐进式披露

方案原文：「让大模型写工具调用的逻辑，可以渐进式纰漏（披露）。」

### 6.1 怎么做

四个工具，披露范围递增：

| 工具 | 输入 | 返回什么 | 不返回什么 |
|---|---|---|---|
| `list_catalog` | 可选 `parent_id` | 当前层子节点的标题、摘要、关键词 | 条款全文 |
| `list_section` | 文件或章节 id | 该层条款号、一句话摘要、`has_table`、`clause_ids` | 条款全文 |
| `read_clause` | 条款 id，如 `3-1-13:第十二条` | breadcrumb + 文号 + **全文** | — |
| `lookup_keyword` | 查询词 | 字面命中列表和 120 字预览 | 不得当作原文引用 |

实现：`backend/tools.py`。Agent 循环：`backend/agent.py`。

渐进式披露在两条线上同时做：

1. **对模型**：先目录后原文；摘要明确写「不是原文」。
2. **对上下文窗口**：`_trim_messages()` 每轮重组——系统提示 + **用户原问题始终保留**；旧的 `list_*` / `lookup_*` 结果压成 id 列表；`read_clause` 只保留最近 `KEEP_FULL_CLAUSES=2` 份全文。

### 6.2 优化点

- 把**章节 id** 误传给 `read_clause` 时，不返回空，而返回该章下的候选条款，提示改用条款 id。
- 检索为空时 hint 要求回到 `list_catalog`，禁止直接宣称未找到。
- 公司 vLLM 对流式 `tool_calls` 曾返回 400（Unterminated string），改为**工具轮非流式补全**，最终答案再按 SSE 切 token。
- 开发机 HTTP 代理导致 httpx SOCKS 报错：`httpx.Client(trust_env=False)`。

方案 370 行「每次调用工具时上下文都可以不同」在 DEMO 里的具体含义就是：下一轮补全看到的是裁剪后的上下文，不是对话里出现过的全部目录 JSON。

### 6.3 效果

召回路径从「一次检索一篇」变成「沿目录往下走」。前端能看见 `list_catalog → list_section → read_clause` 轨迹，便于区分：

- 导航错了（没读到金标准）
- 读到了但没抄对数字
- 无据却编造

对照 IBox：IBox 常混入 2025 文或库外付款规定；DEMO 只引用这 8 份，数字跟 2022 原文（本市出租车 9:30–17:30，津贴分界 17:30）。

## 7. 第 4 步：前后端 DEMO（SSE）

方案原文：「直接让大模型写前后端。」约束：SSE，不要 WebSocket；现有 IBox 前端暂时不管。

### 7.1 怎么做

- 后端：FastAPI `backend/app.py`
  - `POST /api/chat` → SSE：`token` / `tool_call` / `tool_result` / `done` / `error`
  - `POST /api/chat_sync` → 评测用非流式
  - `GET /api/health`、`GET /api/catalog`
- 前端：`frontend/index.html` + `app.js` + `style.css`，静态挂在同一端口
- 模型：OpenAI 兼容接口，默认 `LLM_BASE_URL=http://172.16.120.211:31210/v1`（见 `.env.example`）

侧栏示例题覆盖评测里容易走偏的类型：差旅平台、逾期、公派车辆、紧急出差、津贴、预算无法提交。

### 7.2 优化点

- 界面展示工具轨迹，而不是只给最终段落，方便对照方案「工具召回」是否真的发生。
- 回答结构与 IBox 评测表六段对齐，便于并排看。
- 知识库条款用 `lru_cache` 加载，重抽 PDF 后需重启 uvicorn。

### 7.3 效果

```
cd demo
copy .env.example .env
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

浏览器打开 `http://127.0.0.1:8000` 即可问答。不依赖 IBox 前端，满足「做 DEMO」。

## 8. 第 5 步：把第 2 步收成标准做法，流程闭环

方案原文：「形成 2 这一步的标准做法。流程闭环，5 完成有成果。」

### 8.1 标准做法（可重跑）

一键流水线 `python scripts/run_pipeline.py`：

```
extract_pdfs.py      PDF → 条款 Markdown / JSONL
export_testcases.py  Excel + 金标准 → testcases.json
build_catalog.py     JSONL → catalog.json（条款 ID 校验）
smoke_tools.py       四个工具冒烟
```

目录刷新（可选）：`python scripts/build_catalog.py --llm`

17 题 Agent 评测：`python eval/run_eval.py`  
→ `eval/eval_report.md`、`eval/eval_results.json`

换 PDF、重跑 OCR、改摘要之后，**只要重跑流水线**；目录指向不存在的条款会直接失败。

### 8.3 17 题对照（冻结时的评测快照）

来源：`eval/eval_report.md`（2026-09-17T11:29:26）。IBox 列为原 Excel 评分；DEMO 列为自动判定。

## 9. 优化点总表（跨 0–5 步）

| 问题 | 优化 | 落点 |
|---|---|---|
| IBox 引用库外文件 | 8 份文件夹定界 + 金标准重标 | testcases / 系统提示第 5 条 |
| 2025 vs 2022 数字不同 | 津贴 17:30、本市出租车 9:30–17:30 写入 notes 与 must_not | tc-02、tc-17 |
| 一次塞全文或一次向量检索 | 文件→章→条渐进披露 | catalog + 四工具 |
| 目录选错无法回头 | 字面 `lookup_keyword` + 同义词 | tools.py |
| 32K 被目录 JSON 撑满 | 每轮裁剪，原问保留，条款只留 2 条全文 | agent.py `_trim_messages` |
| 摘要被当成原文 | 提示禁止；数字必须 `read_clause` | prompts.py |
| 表格被抽成乱句 | `find_tables` → Markdown | extract_pdfs.py |
| 扫描件无正文 | Tesseract 切格 OCR | 3-6-1 及表单页 |
| 紧急用车污染出差 | 文件级目录拆开 + 硬约束第 7 条 | 3-1-12 vs 3-1-13 |
| 章节 id 当条款 id | 返回候选条款 | `read_clause` |
| 流式 tool_calls 400 | 工具轮非流式，答案再 SSE | agent.py |
| 代理导致 httpx 失败 | `trust_env=False` | agent / build_catalog |
