## 1. 相对第二轮改了什么

| 项 | 改动 |
|---|---|
| 最终作答真流式 | `ask_stream` 对每轮 `chat.completions` 使用 `stream=True`。工具轮拼完 `tool_calls` 再执行；作答轮在判定为 content 后立刻发 `answer_start`，随后每个 content delta 发 `token`。`force_answer` 在请求发出前就发 `answer_start`。 |
| SSE 协议 | 保留 `tool_call` / `tool_result` / `token` / `done` / `error`；新增 `round_start`、`answer_start`。响应头加 `Cache-Control: no-cache`、`X-Accel-Buffering: no`。 |
| 前端 | 收到 `answer_start` 立即画出【直接回答】标题，正文随 `token` 增长。模型自己打出的开头【直接回答】会去掉，避免双标题。 |
| 添加制度 PDF | 侧栏列表 +「添加 PDF」。`POST /api/ingest` 保存到 `data/uploads/`，抽取（含现有 OCR）、按正文 `第X章/第X条` 拆条、只对新增文件跑 LLM 目录摘要，然后 `reload_kb()` 热加载。 |
| 系统提示 | 「只有 8 份文件」改为按当前 `catalog.json` 动态注入文件清单。 |

## 2. 标准用法

```powershell
cd E:\ibox_qarr\demo
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

- 浏览器打开 `http://127.0.0.1:8000`
- 问津贴/公派车辆等会走工具的题：先出工具轨迹，最后一轮一开始出现【直接回答】并往下长
- 侧栏上传新 PDF 后，知识库计数增加，下一问即可引用新文件（不必重启 uvicorn）

同 `doc_id` 再传同一编号文件会覆盖该文件条款后重建子树。拆不出条时整份落成一条「全文」条款，仍可检索。
