## 1. 相对第三轮改了什么

第三轮已把「最终作答真流式 + 添加 PDF」做成。本轮只改**召回入口**：问题进来后不再直接调工具，先用大模型对照目录判断方向并圈章节。

| 项 | 改动 |
|---|---|
| 路由轮（无工具） | `backend/route.py`。把 `catalog.json` 压成文件+章的标题/摘要/条款号清单（不含原文），交给独立系统提示，只输出 JSON：`direction`、`reason`、`candidates`（2～6 个真实 id）、`maybe_unanswerable`。 |
| 校验 | 候选 id 必须能在目录里找到，幻觉条款号直接丢掉。路由失败或候选为空时，退回原来的根目录注入 + 字面检索。 |
| 注入工具轮 | 路由结果写成「路由判断」块，与字面检索线索一起贴进用户消息。系统提示改为：先 `list_section` 拟引用章节，线索里已有条款 id 则可并行 `read_clause`；禁止按路由硬答。 |
| SSE | 新增 `route_start`、`route`（在第一轮 `round_start` / `tool_call` 之前）。`ask()` 把 `route` 记入 trace。 |
| 前端 | 工具轨迹顶部用蓝色显示「正在判断…」和「方向：…拟引用：…」。 |

路由本身约 8 秒（一次非流式补全，不计工具轮次）。现场抽查与 17 题重跑里的 tc-04 / tc-17 一致：津贴、公派车辆仍能落到第十二/十三条。

### 2.3 怎么读这个结果

- **路由对「一章就能定生死」的题有效**：公派车辆、津贴、住宿超标自理，方向判断与目标章一致。
- **路由会牺牲跨章组合**：交通原则需要第四章第八条+第五章第十三条，只圈第五章就会 miss。城市待遇同理。
- **一次读太多条会伤作答**：tc-10 / tc-14 并行到 20 次，条款在上下文里，答案却漏关键词或宣称未找到。
- 中位耗时多约 6 秒，主要是路由那一轮，不是工具轮次变多。

不建议用本轮数字宣称准确率提升。下一步若要抬分，应让路由输出「可跨章的候选集合」或与字面检索硬融合（方案第 6 步），并限制单轮 `read_clause` 数量。
