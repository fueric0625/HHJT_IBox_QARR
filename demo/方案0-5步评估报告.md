## 3. 分步评估

### 第 0 步：整理测试用例，通读看效果

**方案原意：** 先有评测，才能判断优化是变好还是变坏；通读全文是天花板，用来定目录粒度。

**DEMO 做了什么：**

- 从既有出差评测表导出 17 题到 `demo/data/testcases.json`
- 按库内原文重标：`gold_clause_ids`、必含/禁止关键词、无据标记、分桶（库内无据 / 跨文件 / 精确数字与条款 / 模糊场景 / 术语口语）
- 不经工具、通读抽出全文，写成 `eval/ceiling_report.md`

**做得如何：** 方向正确，且解决了「IBox 高分但引用文件不在 DEMO 库里」的口径混乱。天花板证明：公派车辆在第十三条、津贴在第十二条、紧急出差不能套用车补办——这些后来都写进了目录与提示。

**缺口：** 方案正文阶段 0 建议 200–300 条真实提问和条款级 Recall@5/10。本 DEMO 只有出差 17 题，来源是既有 Excel 而非线上日志；自动指标是「是否 `read_clause` 到金标准 + 关键词」，不是检索 Recall。对出差子集够用，不能外推到全量规章制度。

**评分：达标（范围收缩为出差 17 题后）。**

---

### 第 1 步：第一批测试，大体想法给模型

**方案原意：** 把「分级目录 + 工具取原文 + 只引用原文」交给模型，先跑通再迭代。

**DEMO 做了什么：**

- 系统提示固化工作流：目录/线索 → 并行读条 → 原文作答
- 硬约束：禁止库外文与 2025 口径、禁止摘要当原文、无据须声明未找到、身份锁定为规章制度助手
- 口语到书面语展开（差旅平台→商旅软件、公派车辆→提供交通工具等）
- `eval/run_eval.py` 自动判定 + 与 IBox 原答案对照

**做得如何：** 第一轮已能稳定引用库内条款（差旅平台、无票无房、私车 1 元/公里、逾期等），但导航偏弱：5 题 `miss_clause`，无据题仍编造。第二轮取消「强制先 list_catalog」、首轮注入根目录与检索线索、并行读条之后，目标条款（第十三条、第十二条、无据拒答）均打通。

**缺口：** 提示里有不少针对 17 题的个案约束（公派车辆、紧急补办、17:30）。这会抬本集分数，换制度域要重新写。评测 `likely_ok` 不等于数字抄对，仍需人工抽查。

**评分：达标。** 第一批测试完成了「想法可跑」，第二轮完成了「导航不再系统性走偏」。

---

### 第 2 步：分级目录，由大模型生成

**方案原意：** 离线把制度库编译成文件→章→条目录；`clauses` 只能填真实条款号；产物可复核、可增量重建。

**DEMO 做了什么：**

```
PDF → extract_pdfs.py（条款原子 + breadcrumb + 表格 Markdown / OCR）
    → clauses.jsonl
    → build_catalog.py --llm（摘要 + 条款 ID 校验 + 易混点回写）
    → catalog.json
```

- 层级：file / chapter / clause（及附件）
- 含表条款打 `has_table`，摘要注明须读原文全表
- 文件/章级易混点（公派车辆在第十三条、津贴在第十二条）固化回写，避免 LLM 冲掉
- 第三轮：上传 PDF 后只重建该文件子树并 `reload_kb()`

**做得如何：** 这是本 DEMO 最完整的一步。约 180 个合法条款 ID，目录指向不存在的条款会直接失败。抽取上，数字版表格不再被读成乱序长句；扫描件 3-6-1 可 OCR 出关键数字。模型不必一次塞入全文。

**缺口：**

- 方案要求的生效/废止日期、适用范围等**过滤元数据**未建成；版本隔离靠「库里只有这 8 份」
- 条款过长时「子块检索、父块返回」未做（依赖第 6 步）
- 扫描件小字/流程图仍受 OCR 限制
- 目录质量依赖 LLM 摘要 + 人工易混点，换一批制度需要复核

**评分：达标。** 幻觉校验和可重跑目录是第 5 步「标准做法」的核心。

---

### 第 3 步：工具调用逻辑，渐进式披露

**方案原意：** 一级看目录、二级看摘要、三级读原文；搜错了允许再搜；设轮次上限；无据不编。

**DEMO 工具对照方案建议工具集：**

| 方案建议 | DEMO | 说明 |
|---|---|---|
| `list_catalog(level, parent)` | `list_catalog` | 有 |
| 章节下条款标题+摘要 | `list_section` | 有；按问题排序 |
| `read_clause` | `read_clause` | 有；返回 breadcrumb、全文、`see_also`、`coverage_hint` |
| `search_policy`（混合检索） | `lookup_keyword` | **仅字面检索纠偏，不是 BM25/向量** |

配套编排：

- 每轮裁剪上下文：用户原问保留；旧目录结果压缩；全文只留最近 4 条（`KEEP_FULL_CLAUSES=4`）
- 上限：`MAX_ROUNDS=6`、`MAX_TOOL_CALLS=10`，到达后 `force_answer`
- 交叉引用：从原文抽「参见第 X 条」写入 `see_also`，提示要求并行再读
- 章节 id 误传给 `read_clause` 时返回候选条款，而不是空结果

**做得如何：** 渐进式披露在出差场景上跑通。前端能看见工具轨迹，便于区分导航错误、读到未抄对、无据编造。第二轮后不再每题空转根目录（0/17），10/17 使用并行工具。相对一次性 RAG，公派车辆、津贴、无据题的定位路径明显更稳。

**缺口（方案 4.4 已预警）：** 「只用目录导航是单点失败」。当前纠偏只有字面 `lookup_keyword`，没有混合检索并行融合。跨条款题仍是短板：6 题 `partial`，读到部分金标准但没拼全。这与第 6 步未做直接相关，不视为第 3 步没交付。

**评分：达标。** 工具召回主路径完整；检索托底按方案排期后置。

---

### 第 4 步：前后端 DEMO

**方案原意：** 用大模型写独立 DEMO；SSE 流式；不改现有 IBox 前端。

**DEMO 做了什么：**

- FastAPI：`POST /api/chat`（SSE）、`/api/chat_sync`（评测）、健康检查、目录、文件列表、上传入库
- 单页前端：工具轨迹 + 六段回答结构；第三轮真流式（`answer_start` 后逐 token），不再按 24 字切块
- 侧栏示例题覆盖易走偏类型；可添加 PDF

**做得如何：** 满足「做 DEMO」约束。SSE 协议含 `round_start` / `tool_call` / `tool_result` / `answer_start` / `token` / `done` / `error`。会话内可带 `history`，但不是跨会话产品化。

**缺口：** 不改 IBox、无登录权限、无多用户会话、无引用跳转回 PDF 页码。这些本来就不在第 4 步。

**评分：达标。**

---

### 第 5 步：标准做法与流程闭环

**方案原意：** 第 2 步不能只跑一次，要形成可重复的标准做法；第 5 步完成即有成果。

**DEMO 标准做法：**

```
python scripts/run_pipeline.py     # 抽取 → 用例 → catalog --llm → 冒烟
python eval/run_eval.py            # 17 题 Agent
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

冒烟会检查第十二/十三条关键词、公派车辆导航线索、第八条 `see_also` 指向第十三条。第三轮起，同编号 PDF 再传会覆盖该文件条款后重建子树；拆不出条则整份落成「全文」条款。

**做得如何：** 「换 PDF → 重跑流水线/上传 → 目录校验 → 可问」这条链是通的。成果可复现：代码、知识库、评测集、天花板、Agent 报告、使用说明均在 `demo/`。

**缺口：** 没有删除文件、没有 Word/md 入口、上传后的目录摘要质量仍依赖 LLM、评测不会在入库后自动回归。闭环是工程闭环，不是生产运维闭环。

**评分：达标。** 可以作为第 0–5 步的交付物。

## 4. 端到端效果（相对一次性 RAG / IBox）

优化点不在「向量检索调得更好」，而在召回机制：

| 一次性 RAG 的问题 | 0–5 步是否对上 | 证据 |
|---|---|---|
| 固定切块切断条款 | 已对 | 按条切分；表格整表进条款 |
| 条款号/数字向量表征弱 | 部分对 | 目录带条款号；字面检索；读原文。无 BM25 |
| 口语与书面语鸿沟 | 部分对 | 同义词表 + 目录摘要，非查询改写模型 |
| 跨条款无法一次拼全 | 部分对 | 多轮工具 + `see_also`；6 题仍 partial |
| 版本/库外文件干扰 | 已对（DEMO 边界内） | 8 份锁定 + 禁止引用清单外制度 |
| 改完无法量化 | 已对（小样本） | 17 题金标准 + 自动判定 |

与 IBox 并排时需要主动说明：IBox 高分常来自 2025 出差规定或《付款管理规定》；DEMO 跟 2022 原文（津贴分界 **17:30**，不是 19:30）。因此「谁分更高」不能直接比，要比的是**是否定位到本库金标准条款**。

分桶（第二轮）：

| 分桶 | 题数 | 较好 | 仍弱 |
|---|---|---|---|
| 库内无据 | 1 | 1 | — |
| 术语口语 | 3 | 2 | tc-11 差旅平台停在出差第七条，未读商旅第四/六条 |
| 模糊场景 | 2 | 1 | tc-06 紧急出差关键词未齐 |
| 精确数字与条款 | 8 | 5 | tc-07 城市待遇缺津贴表/附件1；tc-08 超标自理未读第十七条；tc-16 已读逾期条但未写出「3个月」 |
| 跨文件 | 3 | 2 | tc-02 交通原则缺第十六条与报销第十条 |

**结论：** 导航类失败（找不到条）已基本消灭；剩下的是「找到了但没读全/没写全」，正是方案认为需要混合检索与交叉引用继续抬的部分。

## 5. 相对方案四级架构的完成度

方案 4.1 的四层里，0–5 步覆盖的是文档层（结构切分）+ 路由层（目录）+ 编排层（Agent）+ 生成约束；**检索层整体后置**。

```
文档层   ████████░░  按条切分、breadcrumb、原文入库；缺生效/废止过滤元数据
检索层   ██░░░░░░░░  仅字面 lookup；无 BM25、向量、rerank、small-to-big
路由层   ████████░░  三级披露已实现；缺「目录 ∩ 检索」融合
编排层   ███████░░░  工具化、多轮、上限、see_also；跨会话压缩未产品化
生成层   ███████░░░  强制引用、原文作答、无据不答、身份锁定；数字抄写仍需人工核
```

第 5 步完成 = 「分级目录标准做法」有成果，**不是**方案全文四层都做完。

## 7. 未来计划（方案第 6、7、9 步）

以下条目方案原文标为「锦上添花」，**本 DEMO 未做**。建议作为下一阶段，而不是回头推翻第 0–5 步。

### 第 6 步：引入向量化与 BM25

**要解决的问题：** 目录第一层选错无法挽回；跨条款/跨文件题只读到部分金标准（当前 6 题 `partial`）。

**建议做：**

- BM25 与向量并行，结果与目录导航融合（方案 4.3、4.4：不要用目录取代检索，也不要用向量替掉 BM25）
- rerank 后取前若干条，工具形态接近方案中的 `search_policy`
- small-to-big：子块匹配、返回条款全文
- 用现有 17 题先回归，确认 `partial` 能否升到 `likely_ok`，且 `miss_clause` 保持为 0

**验收建议：** tc-02 / tc-07 / tc-08 / tc-11 能读全金标准；模糊题在「提问不含明确条款号」时不低于纯目录。

### 第 7 步：上下文管理

**当前已有雏形：** 每轮丢掉旧目录大段、只保留最近 4 条原文、用户原问始终在场，适配 32K。

**尚未产品化：**

- 跨会话记忆与滚动摘要（方案预算表中的对话历史 ~6K）
- 多轮追问时「上一问的条款」是否仍有效、如何过期
- 工具结果与作答在长对话里的稳定裁剪策略（避免串题，天花板已提示 IBox 在「提前多久」上串过题）

**验收建议：** 连续 3 轮追问不串题、不丢原问、不撑爆 32K；延迟与轮次不明显变差。

### 第 9 步：前后端部署是否合理

**当前：** 单机 uvicorn + 静态页，模型走公司 OpenAI 兼容接口，适合评审演示。

**需要评估：**

- 与现有 IBox 的衔接方式（只改返回 vs 独立入口 vs 替换召回后端）
- SSE 在现网网关/Nginx 上的缓冲（DEMO 已加 `X-Accel-Buffering: no`，未在生产验证）
- 并发、超时、工具轮次导致的尾延迟（中位约 29s，tc-07 曾到 83s）
- 制度更新：增量入库、废止过滤、评测回归是否进入发布流程
- 鉴权、审计、答案溯源到 PDF 页

**验收建议：** 给出「继续独立 DEMO / 接入 IBox 召回 / 全量替换前端」三选一结论，附延迟与运维成本，而不是默认继续堆功能。

## 8. 建议的汇报结论

1. **第 0–5 步 DEMO 已完成。** 出差制度上可以沿分级目录用工具取原文作答，流程可重跑，评测可对比。
2. **相对一次性 RAG 的优化已经发生：** 召回从「相似片段」变成「条款定位」；17 题不再 miss 金标准条款。
3. **准确率尚未到可替换现网的程度：** 11/17 较好，6 题覆盖不全；评测量级小；未接 IBox。
4. **下一步按方案原文走第 6 步（BM25/向量与目录并行）**，优先消化 `partial`；第 7、9 步在效果确认后再投入。
